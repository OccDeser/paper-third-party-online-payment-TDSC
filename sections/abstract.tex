\begin{abstract}
%-------------------------------------------------------------------------------
Third-party online payment systems constitute critical infrastructure for modern e-commerce.
However, their security rests on the unrealistic assumption of fully trusted communication channels. 
While prior studies have identified isolated vulnerabilities, a systematic formal analysis of payment protocol security remains absent. 
We formally model six third-party payment protocols, spanning three major payment scenarios and two dominant payment service providers. 
Our analysis reveals a fundamental design flaw: 
whenever channel integrity is compromised between the merchant client, merchant server, or payment system, order tampering attacks become feasible.
We validate this threat on Android, where over 25\% of tested merchant applications allow order tampering through implicit Intent hijacking.
We propose Sealed Checkout Code (SCC): the merchant frontend seals a fresh nonce to the payment system together with the order handle and the user's account, and the user confirms the payment by entering a short code derived from that nonce.
SCC protects every payment without per-user keys or trust on first use, and formal verification shows that it satisfies all security properties when both external channels are insecure.
By bridging formal methods and empirical analysis, this work offers actionable guidance for standardizing secure payment protocols.
\end{abstract}
